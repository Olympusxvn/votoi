# Feedback for Tatum / organizers - to include at submission

Collected during the build (2026-10-21). The submission form asks "How was your experience building with Walrus?" and "How was your experience building with the Tatum AI Builder?" - paste/adapt the English blurbs below.

## Issues found

1. **Prize pages disagree.** tatum.io/hackathon/total-recall lists the third $500 special as "BEST USE OF AGENT PAYMENTS - Best app across tracks using x402 or MPP, settled on Sui". The Event Rules page (thewalrussessions.wal.app) lists the third special as "Mystery Bounty" (Discord reveal) and never mentions agent payments. The rules page defers to tatum.io as the official event page, so we planned for the agent-payments prize - but the mismatch is confusing for participants.

2. **Tatum Notifications does not support Sui.** The dashboard "Create Alert" wizard offers 24 chains; Sui is absent on both Mainnet and Testnet, and the subscriptions API uses the same chain set. For a Sui hackathon this blocks the standard webhook confirmation flow - we confirm transactions via RPC status checks instead (now through the Tatum native gRPC gateway; see the Nov 6 update below). The generated HMAC webhook handler is ready if Sui support lands.

3. **AI Builder export friction (beta).** The Code view and Publish are marked "Soon"; the only way to get generated code out is "Sync with GitHub". The generated code itself was good (typed, spec-compliant TypeScript).

4. **@tatumio/tatum SDK has no Sui support.** No Sui network/client in v4 - Sui works only through the hosted gateway RPC with @mysten/sui building transactions client-side. Workable, but worth documenting for Sui builders.

## Ready-to-paste (form: "How was your experience building with the Tatum AI Builder?")

> AI Builder generated two production modules for us (a Sui PTB payment module and an HMAC webhook handler) from natural-language prompts - the code was typed and close to spec, and we integrated it after review. Two gaps we hit: the Code view and Publish are still "Soon", so the only export path is Sync with GitHub; and Tatum Notifications does not support Sui yet (24 chains, no Sui), so for a Sui project we confirm transactions via RPC status checks instead of webhooks. One docs note: the two official event pages disagree on the third special prize (agent payments vs Mystery Bounty), which made planning harder than it needed to be. Update Nov 6: the Sui JSON-RPC gateway stopped working for our key on 24 Oct (HTTP 404 on every method, re-verified 4 and 6 Nov); the same key works on the Tatum native gRPC gateway, and our payments now settle through it.

Addendum (2026-10-21): A circulating answer claims the v4 alert API supports Sui (sui-mainnet in the ChainId enum). Checked live with our project key on 2026-10-21: GET /v4/subscription/chains lists 44 chains, none of them Sui, and GET /v4/subscription/types shows no alert type available for any Sui chain. So the gap covers the dashboard, v3 and v4 alike.

Resolution (2026-10-21): Tatum support confirmed in writing that Sui is not currently supported for notifications and pointed us to transaction verification via the Sui RPC Gateway (sui_getTransactionBlock) - which is the approach VOTOI shipped. Appreciate the clear answer; a docs note marking Sui as unsupported for Notifications would still save builders time.

## 2026-10-24: Tatum Sui gateway returns 404 for this project's key
Verified live 2026-10-24: every JSON-RPC method POSTed to https://sui-mainnet.gateway.tatum.io with the project key returns HTTP 404 {"statusCode":404,"message":"Not Found"} - including sui_getChainIdentifier, suix_getBalance, sui_getObject, suix_getOwnedObjects, sui_getTransactionBlock. A bogus key gets 401, so the request shape and URL are correct (and match docs.tatum.io's method list); the route is missing for this key. The same key and code worked live on 2026-10-21 (allowance issue + spend + tx confirmation). Impact in the demo build: chain reads degrade gracefully (status panel flags chainReadsUnavailable, spent totals come from the local ledger); the chat pay flow cannot dry-run/execute until gateway access is restored. Possible causes to ask Tatum about: Sui gateway removed from this free project, or gateway access moved behind a paid RPC plan (the dashboard greys "RPC Calls" behind Upgrade).

## 2026-10-24 (update): Access Logs evidence for the gateway 404
Checked the dashboard's new Access Logs section (signed in, no settings changed). It records BOTH dashboard API calls and gateway RPC calls (product "blockchain-rpc"). Evidence: 71 Sui Mainnet gateway calls on 21 Oct 2026, all 200 OK, resolving Network=sui-mainnet, Blockchain=sui, Interface ID=sui-mainnet-json-rpc. On 24 Oct 13:27-13:33 local, 16 gateway calls to sui-mainnet.gateway.tatum.io all returned 404 in ~1 ms with Network, Blockchain, Interface ID and Gateway ID all EMPTY and "No error log was recorded for this request" (example trace ID 3186381babd4ced97193205f4a6113e1). The gateway edge no longer maps the host to the Sui mainnet interface for this key, so nothing is forwarded. Access Logs does not record the JSON-RPC method name (rows show only POST /), so methods cannot be distinguished there. No other gateway 4xx/5xx in 7 days; the 400s are dashboard data-api calls and the 429s are rate limits, both unrelated.

## 2026-10-24: API farm batch 2 + custom-gateway discovery (scripts/farm-api.ts)
Batch 2: 100 rounds x 17 calls = 1700 calls in 687s, no 429. All 12 Sui gateway methods x100 each = 1200 uniform HTTP 404s {"statusCode":404,"message":"Not Found"}. All 5 Tatum v4 GET endpoints x100 each = 500 calls at 200, including the dashboard management endpoints /v4/manage/limits, /v4/manage/endpoint, /v4/manage/gateway - so those endpoints accept the project API key. Combined farm total so far: 1880 logged calls (1340 gateway 404s, 540 v4 200s), zero rate-limit stops, zero new error types on the generic gateway.
NEW FINDING - custom gateway: /v4/manage/gateway lists a per-account gateway URL (olympusxvn-df8e9414.gateway.tatum.io). Probing it with sui_getChainIdentifier, suix_getBalance, and sui_getLatestCheckpointSequenceNumber all returned HTTP 200 with JSON-RPC error code -16500 "Invalid response from upstream". So the Sui gateway fails TWO different ways depending on URL: the generic sui-mainnet.gateway.tatum.io is not routed at all (HTTP 404, empty Access Logs attribution), while the per-account gateway routes but its Sui upstream returns invalid responses (-16500). The Sui interface itself appears broken server-side, not just unmapped for this key.

## 2026-10-24: Farm conclusion (strategy change: farm only to conclusion, then stop mass batches)
After 2 farm batches (1880 logged calls: 1340 gateway 404s across 12 Sui methods, 540 Tatum v4 200s, zero 429s), the gateway verdict is conclusive and needs no more volume: (1) the generic gateway sui-mainnet.gateway.tatum.io rejects every Sui JSON-RPC method with HTTP 404 at the edge (empty Access Logs attribution, ~1 ms); (2) the per-account gateway URL routes but its Sui upstream fails every method with JSON-RPC error -16500 "Invalid response from upstream". This is a Tatum-side Sui interface outage, not a request, key, or code issue (invalid key gives 401; URL and methods match current docs; the same key worked 2026-10-21). Further farming would only repeat these two signatures. Remaining gateway work: the support ticket (draft in docs/tatum-support-ticket.md) and the JSON-RPC interface itself, still broken as of 6 Nov (see the update below). The Phase 2 pay flow no longer waits on the JSON-RPC gateway: it was re-verified 6 Nov via the Tatum native gRPC gateway (MPP split settled, digest 7V3xpKNHN7eikyPe8N1LbQfLEhSXYgyx92ZhipYJebJC).

## 2026-11-06: JSON-RPC gateway still 404; the same key works on the Tatum Sui gRPC gateway

Re-verified 2026-11-04 and 2026-11-06 with one sui_getChainIdentifier call each: still HTTP 404. The same key works on the Tatum Sui gRPC gateway (sui-mainnet-grpc.gateway.tatum.io:443, x-api-key metadata): GetServiceInfo returned OK in 762 ms, chain mainnet, chainId 4btiuiMPvEENsttpZC7CZ53DruC3MAgfznDbASZ7DR6S, epoch 1303, checkpoint 342138873.

VOTOI moved chain traffic to gRPC-first (commit 8d584cc, src/config/chainTransport.ts), with public Sui gRPC + GraphQL fallback. The 0.003 USD MPP split to 2 recipients settled Nov 6 via gRPC (digest 7V3xpKNHN7eikyPe8N1LbQfLEhSXYgyx92ZhipYJebJC) and was verified on-chain through GetTransaction; gas 3,064,427 MIST (about $0.0026). Public Sui fullnodes reject legacy JSON-RPC ("Method not found... migrate to gRPC or GraphQL"); Sui GraphQL was unreachable from our VM on Nov 6. The Tatum Blockchain MCP routes Sui calls to the same JSON-RPC gateway and returns the same 404, so it does not bypass the outage.

Net effect: the JSON-RPC interface is still broken, but VOTOI no longer depends on it. Updated ask to Tatum: fix the JSON-RPC interface, or confirm it is deprecated in favor of gRPC and point the Sui docs at the gRPC migration path (docs.tatum.io already has a JSON-RPC to gRPC migration guide).
